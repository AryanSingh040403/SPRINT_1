The core Lolo architecture transitioned from a monolithic design to an LLM Agent with MLOps. For our core reasoning engine, we initially tested the Qwen1.5-1.8B model due to its small memory footprint. However, we encountered the 'parameter wall' where the 1.8B model struggled with complex ReAct formatting and suffered from hallucinations. Therefore, we upgraded our final architecture to use the Meta Llama-3.1-8B-Instruct model. We chose Llama 3.1 because its superior reasoning capabilities completely eliminated ReAct loops and hallucinations while still running natively on an Apple Silicon GPU. For our vector database retrieval system, we use FAISS. To generate vectors for FAISS, we use the all-MiniLM-L6-v2 embedding model because it is highly optimized for local CPU execution. When processing documents, our chunking strategy uses the RecursiveCharacterTextSplitter set at 600 tokens with a 100-token overlap to ensure context is not lost between paragraph breaks
